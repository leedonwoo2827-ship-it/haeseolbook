# 기기 무관 서비스 연구: 웹(PWA) 단일 코드 + 앱 셸

- 작성일: 2026-10-19
- 결론: **웹(PWA) 한 벌로 모든 OS를 지원**한다. 앱은 출판사 사이트 URL을 띄우는 얇은 셸(Tauri·Capacitor)로 둔다.
- 서버는 Cafe24 리눅스 호스팅(PHP + MySQL, 그누보드 사이트와 같은 도메인)에 둔다.

## 1. 운영체제별 3가지 접근 경로

| OS | ① 브라우저 | ② PWA 설치 | ③ 앱 셸 | 비고·리스크 |
|---|---|---|---|---|
| Windows | ✅ Chrome/Edge | ✅ "앱 설치" | ✅ Tauri(NSIS) | 캡처 차단은 ③에서만(`contentProtected` → SetWindowDisplayAffinity). 코드 서명 인증서 필요 |
| macOS | ✅ Safari/Chrome | ✅ Safari 17+ "Dock에 추가" | ✅ Tauri(.dmg) | Apple 공증(개발자 계정) 필요. 캡처 차단은 제한적 |
| Linux | ✅ Chrome/Firefox | ✅ Chrome | ✅ Tauri(AppImage/.deb) | 캡처 차단 API가 없어 워터마크만 쓴다. WebKitGTK의 펜 압력 지원이 약하다 → 중간 리스크 |
| iPadOS/iOS | ✅ Safari | ✅ 홈 화면 추가 | ✅ Capacitor | PWA 저장소는 오래 쓰지 않으면 지워질 수 있다 → 필기는 서버 동기화가 기본. Pencil 압력 지원(PointerEvent) |
| Android | ✅ Chrome | ✅ WebAPK | ✅ Capacitor | S Pen 압력 지원. FLAG_SECURE로 캡처 차단 가능 |

- **판정:** 큰 리스크가 없어 세 경로를 모두 반영했다.
- **블로커는 아니지만 알려진 제약:**
  - Linux 셸의 캡처 차단
  - iOS PWA 저장소 삭제 가능성
  - 스토어 심사(앱 셸의 "웹 래퍼" 정책)

## 2. 왜 웹이 기본인가

1. **유튜브 연동이 가장 쉽다.** IFrame Player API는 브라우저에서 1급으로 지원된다. 네이티브에서는 WebView로 감싸야 하고, 번들 파일(`tauri://`, `capacitor://`)에서는 referrer가 없어 임베드 오류(153 등)가 나기 쉽다.
   → 앱 셸도 **사이트 URL을 그대로 로드**(`https://…/exam/ebook/`)해 같은 출처와 referrer를 보장한다.
2. **출판사 사이트(그누보드)와 같은 도메인**이라 회원 세션을 그대로 쓴다(SSO). CORS도 필요 없다.
3. **배포가 한 번이다.** FTP로 올리면 PWA, Tauri, Capacitor가 모두 즉시 갱신된다. 스토어 재심사는 셸 기능이 바뀔 때만 필요하다.
4. **필기 성능:** Pointer Events, `getCoalescedEvents`, perfect-freehand 조합으로 Pencil/S Pen 압력을 반영한다. 2레이어 캔버스(확정 획 / 그리는 중인 획)로 다시 그리기 비용을 줄였다. 목표는 지연 50 ms 미만이다(실기기 측정 필요).

## 3. 기기 간 동기화

- 필기는 **페이지 단위 문서**(`InkPage`)로 다룬다. 좌표는 0–1 정규화라 화면 크기와 무관하다.
- 로컬 우선:
  - IndexedDB에 즉시 저장한 뒤 1.5초 디바운스로 `PUT /ink`를 보낸다.
  - 오프라인이면 쌓아 두었다가 `online` 이벤트 때 보낸다.
- 충돌 처리:
  - 서버 `rev`가 앞서면 `conflict`를 돌려준다.
  - 클라이언트는 `mergeInk`(획 id 합집합, 삭제 기록 반영)로 합친 뒤 새 baseRev로 재시도한다.
  - 같은 내용을 다시 보내면 멱등 OK다.
- 다른 기기의 필기는 30초 간격 증분 pull(`updatedAfter`)과 화면 진입 시 pull로 받는다.
- 채점 기록은 서버에 저장한다. 오프라인이면 로컬로 채점한다(정답이 매니페스트에 있다. 무료 교재라 허용).

## 5. 유튜브 해설영상 규격 권고

- **본편은 가로 16:9(1920×1080)로 만들고, 회차당 한 편에 문항별 챕터를 둔다.**
  - PC·태블릿에서는 원문 옆 패널에, 폰에서는 위쪽 띠(화면 높이의 약 1/4)에 고정된다. 세로 영상은 폰에서 원문을 가린다.
  - 2단 시험지의 한 문항 영역은 가로형(약 0.49 × 0.18 페이지)이라 확대해 풀이하기에 16:9가 맞다.
  - `video_map.json`(문항별 startSec/endSec)이 한 편 + 챕터 구조와 그대로 대응한다.
- **세로 9:16 쇼츠는 홍보용으로만** 쓴다. 인기 문항을 같은 소스에서 잘라 내고 리더와는 연결하지 않는다.
- 영상 화면이 원문을 그대로 확대한 것이면, AI가 넘기는 포인터 좌표(`cues`)를 원문 0–1 좌표로 바로 바꿀 수 있다.
